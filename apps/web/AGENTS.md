# Web application instructions

- Make repo import, rankings, graph exploration and practice easy to reach. Keep career planning and portfolio evidence linked to the main flow. Use one navigation, account state and skill vocabulary.
- Distinguish file imports, external packages and function calls by edge labels and direction. Show incoming and outgoing links and the cited source. Mark unclear calls as unresolved and keep visual graph exploration usable at file and function scales.
- Show rubric weights, evidence, coverage and comparable rank with each scorecard. Keep the story, input/output contract, sample cases, submission and results clearly structured on each coding test.
- Always provide a usable loading, empty, partial, error and retry state. Expose the revision and coverage next to repository findings, and offer a keyboard-accessible list and detail view alongside graph interactions.
- Show what will be stored or sent when asking for consent. Keep provider keys in tab memory and clear them on reload. Use a relative same-origin API and render external content as escaped data.
- Display the actual evaluation method for each proof and connect scoring to server results. Let users inspect source citations and their contribution claims before creating evidence.
- Run the applicable lint, type check, production build and browser journeys. Check mobile widths, keyboard navigation and focus restoration, stale data and provider degradation for changed flows.
