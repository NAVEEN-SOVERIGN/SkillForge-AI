# Verification instructions

- Map each release test to a PRD requirement and record whether it uses fixtures, local services or staging providers. Use synthetic identities, public test repositories and isolated stores.
- Characterize source behavior with reproducible fixtures before porting algorithms. Include grading, scoring, approval transitions, citation validity, repository coverage and saved-state authorization.
- Exercise GitHub paste and picker, pinned scans, scorecard ranking, code graph drill-down and a scenario-test submission. Test fixture edges for cross-file calls, package and aliased imports, and ambiguous dispatch. Check score ties, partial coverage, stale rubrics and AI unavailability.
- Verify hidden tests, judge limits and isolation. Exercise the follow-on path from repo findings and assessment through portfolio, approved action, readiness and PDF. Verify unsupported evidence earns no verification credit and repeat submission adds no duplicate credit.
- Include access-denial coverage across accounts, graph snapshot swaps, quota errors, retries, cleanup and stale sessions. Use staging provider smoke checks when credentials are provisioned. Keep values, resume text and provider payloads out of artifacts.
