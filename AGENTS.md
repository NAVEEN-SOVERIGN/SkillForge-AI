# Repository instructions

Read [the PRD](docs/PRD.md), [build plan](docs/BUILD_PLAN.md), [source inventory](docs/SOURCE_INVENTORY.md), and [environment guide](docs/ENVIRONMENT.md) before implementing a milestone. Follow any nested `AGENTS.md` in the directory you change.

- Prioritize GitHub import, repository scorecards, the code structure graph, and scenario-based tests. Use a single account identity, skill taxonomy and evidence ledger. Keep repo quality and assessment results as distinct measures. Start with a requirement ID and its acceptance criteria.
- Work in this repository. Treat the upstream clone and local Hackfront checkout as reference inputs. Record pinned revisions and reuse permission before importing source, assets or data. Reimplement behavior independently where reuse rights are unavailable. Keep reference accounts, secrets, generated media and project caches outside this repo.
- Use source inspection for source-backed facts. Apply the reverse-engineer-anything workflow to a supplied build or an isolated runtime scenario when source alone cannot resolve a behavior. Record revisions, observations, inferences and remaining unknowns. Use fixture data and never capture credentials or user content.
- Keep repository source, history, resumes, submissions and model output untrusted. Analyze imported code statically. Run scenario-test submissions only in the isolated evaluator. Enforce ownership on reads and writes. Keep provider secrets server-side except tab-scoped BYOK, which stays in memory. Use explicit consent for transmitting repository evidence to a model and for saving a temporary index.
- Verify changes through the normal product entry point. Run the checks available for the touched layers and report what ran, what passed, and any provider or staging checks still pending. Keep docs and acceptance criteria synchronized with changes in behavior.
- Keep commits narrowly scoped. Use the integrated repo's configured remote only when the user requests publication. Keep live credentials and production data out of commits, logs and example files.
